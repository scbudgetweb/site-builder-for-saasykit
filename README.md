# Site Builder for SaaSykit

**Build your SaaSykit app's marketing site in the admin panel.** Drag-and-drop pages, headers and footers from 45+ blocks, with live preview, layers, revisions and your brand everywhere. No page builder subscription, no external services, and it runs happily on shared hosting.

> An independent add-on for [SaaSykit](https://saasykit.com). It isn't made or endorsed by SaaSykit. You need your own SaaSykit licence.

## What's inside

- **A visual builder** with live preview, drag and drop, a layers panel, undo and redo, right-click menus, copy and paste styles, and phone, tablet and desktop views. Or edit the same page as a form.
- **45+ blocks:** heroes, banners, features, pricing tables, testimonials, team, FAQ, tabs, stats, counters, a countdown, galleries, video, audio, maps, contact forms, mailing list sign-ups, blog posts and more. Sections hold rows of up to five columns.
- **A theme builder** for headers and footers, starting from ready-made layouts: a top bar, a header that stays at the top, shrinks or sits over the first section, a mobile menu with style, and Back to top.
- **Blog templates** for SaaSykit's blog posts and archives.
- **Branding** in one place: logos, colours, fonts, buttons, corners, shadows, header and footer colours and banners, used by every block and SaaSykit's own pages and dashboards.
- **A media library**, **block library**, **revisions**, **navigation menus**, **contact messages**, **mailing lists** (Brevo) and **legal pages**.
- **Privacy built in:** fonts and icons are stored on your site, and videos, maps, SoundCloud and Spotify wait for cookie consent.

## Built for shared hosting

The site builder needs nothing beyond what SaaSykit needs, and asks less of the server than most:

- **No queue worker:** emails from forms are sent straight away.
- **No Node.js on the server:** run `npm run build` once on your computer and upload `public/build`.
- **No external services:** fonts, icons and images are served from your own site; nothing calls home.
- **Fast pages on a small server:** a page's HTML is cached (any cache store, including files), with the parts that change per visitor filled in on each request.
- **Uploads within your host's limits:** Website › Media shows PHP's upload limit beside each setting, never lets a setting exceed it, and can shrink large photos as they arrive.
- **One cron line** runs everything scheduled: `* * * * * php /path/to/artisan schedule:run`.

Uploads use Laravel's `public` disk, so run `php artisan storage:link` once. If your host doesn't allow symlinks, point `site-builder.uploads.disk` at a disk whose root is inside `public/`.

## Requirements

- PHP 8.3+
- Laravel 12 or 13
- Filament 5
- A SaaSykit (or SaaSykit Tenancy) app
- Optional: `intervention/image` ^4 for shrinking photos and removing location data as they're uploaded

## Installation

1. Require the package:

   ```bash
   composer require scbudgetweb/site-builder-for-saasykit
   ```

2. Run the installer. It publishes `config/site-builder.php`, runs the migrations (after asking), publishes the bundled fonts and prints the lines below:

   ```bash
   php artisan site-builder:install
   ```

   Migrations are loaded from the package, so later updates only need `php artisan migrate`.

3. Add the plugin to your admin panel provider:

   ```php
   ->plugin(\ScBudgetWeb\SiteBuilder\SiteBuilderPlugin::make())
   ```

4. Add these lines to `resources/css/app.css`, then run `npm run build`:

   ```css
   @import '../../vendor/scbudgetweb/site-builder-for-saasykit/resources/css/site-builder.css';
   @source '../../vendor/scbudgetweb/site-builder-for-saasykit/src';
   @source '../../vendor/scbudgetweb/site-builder-for-saasykit/resources/views';
   ```

   Tailwind only includes classes it finds in its sources, and some of the package's classes are chosen in PHP, so both `@source` lines are needed.

5. Schedule the package's commands in `routes/console.php`:

   ```php
   // Straight after SaaSykit's sitemap, which rewrites robots.txt.
   Schedule::command('app:generate-sitemap')->everyOddHour()->then(fn () => Artisan::call('site-builder:sitemap'));

   // Uploads abandoned before they reached the media library, and Branding images, that nothing uses (older than a day).
   Schedule::command('site-builder:clean-uploads')->daily();

   // Contact form messages older than site-builder.contact.keep_days.
   Schedule::command('model:prune', ['--model' => [\ScBudgetWeb\SiteBuilder\Models\ContactMessage::class]])->daily();
   ```

## The theme

The theme puts its own views in front of SaaSykit's without editing any of SaaSykit's files:
- header, footer and navigation;
- layouts;
- a plain home page (which a page can replace);
- the blog index, categories and posts;
- the Privacy Policy and Terms of Service.

Switch the theme off with `SITE_BUILDER_THEME=false`. After a SaaSykit update, compare SaaSykit's versions of these views with the theme's.

Views are found in this order:
1. the app's own theme folder, `resources/views/theme`, when it's in `config/view.php`'s `paths`;
2. the package's theme;
3. SaaSykit's views (`resources/views`).

So to change one theme view, copy it from the package's `resources/views/theme/` into the same place under the app's `resources/views/theme/` and edit it there. For example, `components/layouts/app/header.blade.php` changes only the header, and the rest of the theme still comes from the package.

Your copy doesn't update with the package. After each package update, check the CHANGELOG for theme changes, `diff` your copy with the package's in `vendor/scbudgetweb/site-builder-for-saasykit/resources/views/theme/`, and bring the changes across. The [extending guide](docs/developers/extending.md#overriding-a-theme-view) has more.

## Configuration

| Key | Default | What it does |
|---|---|---|
| `navigation.group` / `icon` / `collapsed` | Website, globe, collapsed | The admin navigation group |
| `theme.enabled` | `true` (`SITE_BUILDER_THEME`) | The base theme |
| `theme.app_path` | `resource_path('views/theme')` | The app's own theme folder, whose views win over the theme's when it's in `view.paths` |
| `permissions.*` | see above | The permission each area needs |
| `pages.routes` | `true` | Serve pages at `/{slug}` (a fallback route, so a page never hides an app route) |
| `pages.preview_path` | `site-builder/preview` | Where signed previews live |
| `pages.revisions` | `30` | Revisions kept per page |
| `pages.cache` | `true` (`SITE_BUILDER_PAGE_CACHE`) | Cache the HTML of pages whose blocks are all cacheable |
| `uploads.disk` / `directory` | `public` / `site-builder` | Where logos, page images and Audio blocks' sound files are stored |
| `contact.keep_days` | `365` (`SITE_BUILDER_CONTACT_KEEP_DAYS`) | How long contact form messages are kept |
| `livewire_upload_size` | `true` | Raises Livewire's temporary upload limit (`temporary_file_upload.rules`' `max:`) to the largest image or sound file set in Website › Media, and its `max_upload_time` to 30 minutes, never lowering them. `false` leaves them alone |
| `livewire_nesting_depth` | `48` | Raises Livewire's `payload.max_nesting_depth` to this (never lowers it, at most 128), so lists, tables and quotes in rich text can be edited in the builder's panels. `false` leaves Livewire's setting alone |

## Extending it

A host app registers its own blocks, replaceable built-in pages, menu links (or removes standard ones), live stats, Branding colours and sections, legal pages and cookie-consent checker through the `SiteBuilder` facade:

```php
use ScBudgetWeb\SiteBuilder\Facades\SiteBuilder;

SiteBuilder::blocks([OpeningHoursBlock::class])
    ->slots([Slot::make('contact', 'Contact', fn () => route('contact'))->requires('contact_form')])
    ->links([Link::make('find_a_hall', 'Find a hall', fn () => route('halls.index'))])
    ->withoutLinks(['pricing'])
    ->stats(['halls' => ['Halls listed', fn () => Hall::count()]])
    ->brandingColours('Booking widget', ['booking_bg' => ['Background colour', '--color-booking-bg']])
    ->brandingSection('signup', 'Sign-up box', [BrandingField::text('signup_title', 'Title')])
    ->legalPages([LegalPage::make('cookie_policy', 'Cookie Policy', fn () => route('cookie-policy'))])
    ->consentChecker(fn (string $category): bool => CookieConsent::allows($category));
```

See the [developer guides](docs/README.md#for-developers-and-agents).

## Testing

```bash
composer install
composer test
```

The tests always use an in-memory SQLite database, even if your shell sets `DB_*` variables, because they reset the database as they run. To run them against MySQL, copy `phpunit.xml.dist` to `phpunit.xml` (it's git-ignored) and change `DB_CONNECTION` there.
